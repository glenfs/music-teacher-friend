## Performance Issues (Menu-Specific)

### 1. STYLEBOX DUPLICATION ON EVERY REFRESH ⚠️ HIGH IMPACT

**Location:** Multiple `_refresh_*` functions
**Pattern:** `StyleBoxFlat.new()` + `.duplicate()` called repeatedly

**Examples:**
```gdscript
# Line ~5690 _style_button()
var normal := StyleBoxFlat.new()  # NEW every call
var hover := normal.duplicate()    # DUPLICATE every call
var pressed := normal.duplicate()  # DUPLICATE every call

# Line ~5740 _style_settings_button()
var normal := StyleBoxFlat.new()
var hover := normal.duplicate()
var pressed := normal.duplicate()

# Line ~5780 _style_interval_option_toggle()
var normal := StyleBoxFlat.new()
var hover := normal.duplicate()
var pressed := normal.duplicate()

# Line ~6260 _style_menu_toggle()
var normal := StyleBoxFlat.new()
var hover := normal.duplicate()
var pressed := normal.duplicate()
```

**Impact:**
- Every button style refresh creates 3+ StyleBox objects
- Menu has 50+ buttons → 150+ StyleBox allocations per theme change
- GC pressure when switching themes/modes

**Affected Functions:**
- `_style_button()` - Called for every hub/mode button
- `_style_settings_button()` - Called for settings buttons
- `_style_interval_option_toggle()` - Called for 8 degree toggles
- `_style_menu_toggle()` - Called for inversion/accidental toggles
- `_refresh_practice_setup_theme()` - Calls all above on every theme switch

**Fix:**
```gdscript
# Pre-create in _ready()
var _button_styles: Dictionary = {
    "normal": StyleBoxFlat.new(),
    "hover": StyleBoxFlat.new(),
    "pressed": StyleBoxFlat.new()
}

# Reuse in _style_button()
btn.add_theme_stylebox_override("normal", _button_styles["normal"])
```

### 2. THEME PALETTE RECREATION ⚠️ MEDIUM IMPACT

**Location:** Line ~5500 `_theme_button_palette()`
**Pattern:** Large dictionary created on every call, cached but cache invalidated

**Current Code:**
```gdscript
var _cached_button_palette: Dictionary = {}

func _theme_button_palette() -> Dictionary:
    if not _cached_button_palette.is_empty():
        return _cached_button_palette
    # ... 200 lines of dictionary creation ...
    _cached_button_palette = result
    return result
```

**Issue:**
- Cache is cleared when theme changes
- Theme changes on every mode switch
- Dictionary has 15+ color entries × 5 themes = large allocation

**Fix:**
```gdscript
# Pre-create all palettes in _ready()
var _theme_palettes: Dictionary = {
    "golden_harvest": {...},
    "azure_cascade": {...},
    # ... pre-computed
}

func _theme_button_palette() -> Dictionary:
    return _theme_palettes.get(_current_theme, _theme_palettes["golden_harvest"])
```

### 3. BUTTON HOVER FEEDBACK TWEENS ⚠️ MEDIUM IMPACT

**Location:** Line ~5879 `_connect_card_hover_feedback()`
**Pattern:** New tween created on every hover enter/exit

**Current Code:**
```gdscript
var hover_enter := func() -> void:
    var tw := card.create_tween()  # NEW tween every hover
    tw.tween_property(card, "scale", Vector2(1.025, 1.025), 0.12)
    
var hover_exit := func() -> void:
    var tw := card.create_tween()  # NEW tween every hover
    tw.tween_property(card, "scale", Vector2.ONE, 0.15)
```

**Impact:**
- User hovers over 10 buttons → 20 tweens created
- Tweens not pooled or reused
- Memory churn during menu navigation

**Fix:**
```gdscript
# Use AnimationPlayer instead
var _hover_anim: AnimationPlayer

func _ready():
    _hover_anim = $HoverAnimationPlayer
    
func _on_button_mouse_entered():
    _hover_anim.play("scale_up")
```

### 4. DYNAMIC NODE CREATION IN _build_ui() ⚠️ HIGH IMPACT

**Location:** Line ~2108 `_build_ui()` and children
**Pattern:** Hundreds of `Label.new()`, `Button.new()`, `PanelContainer.new()`

**Examples:**
```gdscript
# Line ~2200+ Header construction
var brand_label := Label.new()
_header_card = PanelContainer.new()
var hud_bg := TextureRect.new()
var hud_margin := MarginContainer.new()

# Line ~2400+ Home card construction
_home_card = PanelContainer.new()
_home_scroll = ScrollContainer.new()
_home_panel = VBoxContainer.new()

# Line ~4787 _create_home_option_group()
var panel := PanelContainer.new()
var margin := MarginContainer.new()
var content := VBoxContainer.new()
```

**Impact:**
- 200+ nodes created on startup
- Slow initial load time (2-5 seconds on mobile)
- All node setup done procedurally vs. instanced scenes

**Fix:**
```gdscript
# Extract to scenes:
const HeaderCardScene = preload("res://ui/components/HeaderCard.tscn")
const HomeOptionGroupScene = preload("res://ui/components/HomeOptionGroup.tscn")

# In _build_ui():
_header_card = HeaderCardScene.instantiate()
var panel = HomeOptionGroupScene.instantiate()
```

### 5. SETTING ROW CREATION IN SETTINGS SCREENS ⚠️ MEDIUM IMPACT

**Location:** Line ~2570+ Settings construction
**Pattern:** Uses UIManager but still creates nodes dynamically

**Current Code:**
```gdscript
var interval_degree_row: Node = _ui_manager.create_setting_row(...)
var interval_row: HBoxContainer = _ui_manager.setting_row_content(...)

# Then creates degree buttons:
for degree in range(1, 9):
    var degree_btn: Button = _ui_manager.create_option_chip(...)
    interval_row.add_child(degree_btn)
```

**Issue:**
- UIManager helps but still creates nodes at runtime
- OptionChip scene exists but buttons created in loop
- 8 degree buttons + 10 chord buttons + 16 progression buttons = 34+ buttons

**Fix:**
```gdscript
# Pre-instantiate option chips in _ready()
var _degree_chips: Array[Button] = []

func _cache_degree_chips():
    for i in range(8):
        var chip = OptionChipScene.instantiate()
        chip.text = str(i + 1)
        _degree_chips.append(chip)
        chip.visible = false  # Hide until needed
        add_child(chip)

# Reuse in settings:
for i in range(8):
    var chip = _degree_chips[i]
    chip.visible = true
    interval_row.add_child(chip)
```

### 6. TEXT FORMATTING IN REFRESH LOOPS ⚠️ LOW IMPACT

**Location:** Multiple `_refresh_*` functions
**Pattern:** String formatting every refresh call

**Examples:**
```gdscript
# Line ~9500 _refresh_home_subtitle()
if _is_ear_training_mode():
    _home_title_label.text = "Ear Training"
elif _selected_mode == MODE_SIGHT:
    if _sight_mode == "Chords":

# Line ~7683 _build_sight_hearts_text()
return "❤".repeat(lives)  # String repeat every call
```

**Impact:**
- Strings allocated every refresh
- Called multiple times per second during transitions

**Fix:**
```gdscript
# Cache formatted strings
var _mode_titles: Dictionary = {
    MODE_INTERVAL: "Ear Training",
    MODE_SIGHT: "Sight Reading",
    MODE_NOTE_CHASE: "Note Chase"
}

func _refresh_home_subtitle():

```

### 7. call_deferred() OVERUSE ⚠️ LOW IMPACT

**Location:** Line ~1040, 12844, 13046+
**Pattern:** Deferred calls for layout that could be immediate

**Examples:**
```gdscript
# Line ~1040 _ready()
call_deferred("_post_layout_init")
call_deferred("_update_game_card_layout")
call_deferred("_enforce_startup_home_overview")

# Line ~12844 _show_home()
call_deferred("_setup_home_focus_navigation")

# Line ~13046+ Various
call_deferred("_position_tutorial_button_row")
call_deferred("_position_tutorial_title")
call_deferred("_position_tutorial_end_buttons")
```

**Issue:**
- Some deferrals are necessary (tree not ready)
- Many could be immediate after layout is stable
- Extra frame delay for no benefit

**Fix:**
```gdscript
# Only defer when tree is not ready
if not is_node_ready():
    await ready
_setup_home_focus_navigation()  # Direct call
```

### 8. SCROLL CONTAINER LAYOUT RECALCULATION ⚠️ MEDIUM IMPACT

**Location:** Line ~2380 _home_scroll setup
**Pattern:** ScrollContainer with dynamic content causes layout thrashing

**Current Code:**
```gdscript
_home_scroll = ScrollContainer.new()
_home_scroll.follow_focus = true  # Causes scroll on every focus change
_home_panel.add_theme_constant_override("separation", 18)  # Triggers relayout
```

**Issue:**
- `follow_focus = true` scrolls on every button focus
- Theme constant changes trigger full relayout
- 50+ buttons = 50+ scroll operations on navigation

**Fix:**
```gdscript
_home_scroll.follow_focus = false  # Manual scroll control

# Batch layout changes:
_home_panel.set_process(false)  # Pause processing
_home_panel.add_theme_constant_override("separation", 18)
# ... other changes ...
_home_panel.set_process(true)  # Resume (single relayout)
```

### 9. VISIBILITY TOGGLING WITHOUT CACHING ⚠️ LOW IMPACT

**Location:** Multiple `_refresh_*` functions
**Pattern:** Setting `.visible` without checking current state

**Examples:**
```gdscript
# Line ~12900 _show_home()
if _tutorial_panel != null:
    _tutorial_panel.visible = false  # Set even if already false
if _tutorial_bubble != null:
    _tutorial_bubble.visible = false

# Line ~4712 _refresh_background_scene_emphasis()
if _home_menu_overlay != null:
    _home_menu_overlay.visible = home_visible  # Set every call
```

**Issue:**
- Godot processes visibility changes even if no actual change
- Unnecessary dirty flag setting

**Fix:**
```gdscript
if _tutorial_panel != null and _tutorial_panel.visible:
    _tutorial_panel.visible = false  # Only if currently visible

# Or cache state:
if _tutorial_panel != null:
    _tutorial_panel.visible = false
    _tutorial_panel_was_visible = false  # Track state
```

### 10. SIGNAL CONNECTIONS IN LOOPS ⚠️ LOW IMPACT

**Location:** Line ~9560+ Toggle handlers
**Pattern:** Signals connected without cleanup consideration

**Examples:**
```gdscript
# Line ~9566 _on_degree_toggled
func _on_degree_toggled(enabled: bool, degree: int):
    # Called 8 times (once per degree button)
    
# Line ~9630 _on_progression_toggle
func _on_progression_toggle(enabled: bool, progression_id: String):
    # Called 16 times (once per progression button)
```

**Issue:**
- Each button has pressed/toggled signals
- 50+ buttons = 100+ signal connections
- No disconnect on scene change

**Fix:**
```gdscript
# Use Callable bindings instead of named functions
for degree in range(1, 9):
    var chip = _degree_chips[degree - 1]
    chip.toggled.connect(_on_degree_toggled.bind(degree))
    # Consider: Disconnect in _exit_tree()
```

## Performance Recommendations (Prioritized)

### CRITICAL (Do First - Menu Startup)

1. **Cache StyleBox Resources** - Pre-create in `_ready()`
   - Impact: 80% reduction in style allocations
   - Effort: Medium (2-3 hours)
   - Expected: +10-15 FPS during menu navigation

2. **Extract UI to Instanced Scenes** - HeaderCard, OptionGroup, ModeCard
   - Impact: 50% faster menu startup
   - Effort: High (6-8 hours)
   - Expected: -1-2 seconds initial load time

3. **Pre-instantiate Repeated Buttons** - Degree chips, chord buttons
   - Impact: Eliminate runtime button creation
   - Effort: Low (1 hour)
   - Expected: Smoother theme transitions

### HIGH (Menu Navigation)

4. **Replace Hover Tweens with AnimationPlayer**
   - Impact: Eliminate tween churn on hover
   - Effort: Low (1 hour)
   - Expected: No GC spikes during navigation

5. **Cache Theme Palettes** - Pre-compute in `_ready()`
   - Impact: Instant theme switches
   - Effort: Low (30 min)
   - Expected: No frame hitch on mode change

6. **Batch Layout Changes** - Disable/enable processing
   - Impact: Single relayout vs. multiple
   - Effort: Low (1 hour)
   - Expected: +5 FPS during settings changes

### MEDIUM (Polish)

7. **Reduce call_deferred Usage** - Only when necessary
   - Impact: Faster menu transitions
   - Effort: Low (1 hour)
   - Expected: -1 frame delay

8. **Cache Formatted Strings** - Mode titles, heart symbols
   - Impact: Less string allocation
   - Effort: Low (30 min)
   - Expected: Marginal GC improvement

9. **Conditional Visibility Updates** - Check before setting
   - Impact: Less dirty flag setting
   - Effort: Low (1 hour)
   - Expected: Marginal CPU improvement
