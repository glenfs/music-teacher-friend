A. SIGNAL CONNECTION PATTERNS
================================================================================

A1  ALL ~85 CONNECTS HAPPEN ONCE IN _build_ui() — SAFE
    All signal connections are made during _build_ui() (lines 2313-4617).
    No connections are made inside per-frame or per-mode-change paths.
    No disconnect() calls exist because all connected nodes share the same
    lifetime as the root scene — no leak risk.
    Status: ACCEPTABLE AS-IS.

A2  _on_menu_gloss_host_resized: GUARD EXISTS, MULTIPLE LAMBDAS DO NOT
    File: interval_birds.gd, line 5514-5516

    _menu_top_gloss_ensure() correctly guards against duplicate connects:
      if not ctrl.has_meta("menu_gloss_resize_connected"):
          ctrl.set_meta("menu_gloss_resize_connected", true)
          ctrl.resized.connect(_on_menu_gloss_host_resized.bind(ctrl))

    However, several one-shot animation functions connect lambda callbacks
    directly to tween.finished without any guard:
      Line 7762:  tw.finished.connect(func() -> void: ...)
      Line 7800:  _sight_streak_anim_tween.finished.connect(...)
      Line 14557: tw.finished.connect(func() -> void: ...)
      Line 14583: tw.finished.connect(func() -> void: ...)
      Line 19512: vanish_tw.finished.connect(func() -> void: ...)
      Lines 21979, 21993, 22006: three bird animation tween.finished lambdas

    Tweens are single-use and freed after completion so these lambdas are
    freed with the tween — no accumulation. ACCEPTABLE AS-IS.

A3  hover_enter / hover_exit / button_down LAMBDAS AT LINES 5955-5984
    _setup_home_section_card() and nearby helpers connect hover/press lambdas
    to mode cards. These are called once per card at _build_ui() time.
    Each card gets 3 signals × ~8 cards = ~24 lambda closures held alive.
    These capture local variables (tw, card, btn). No issue — controlled
    lifetime, freed when scene exits.
    Status: ACCEPTABLE AS-IS.

B. TWEEN AND TIMER PATTERNS
================================================================================

B1  _set_sight_streak_display_values(): 2 TWEENS CREATED WITHOUT KILL GUARD
    File: interval_birds.gd, lines 7786-7792

    This function creates two create_tween() calls:
      var t1 := create_tween()   # line 7786
      var t2 := create_tween()   # line 7792

    These are created inside an else-branch (not the animating path) but
    there is no pre-existing tween reference stored for t1/t2 individually.
    Only _sight_streak_anim_tween (killed at line 7774) is tracked. If this
    function is called repeatedly (e.g. rapid answer feedback), t1 and t2
    from the previous call may still be running and will overlap.

    Fix: Store t1/t2 as instance vars and kill before recreating:
      var _sight_streak_flash_tween_1: Tween = null
      var _sight_streak_flash_tween_2: Tween = null
      if _sight_streak_flash_tween_1 != null and is_instance_valid(_sight_streak_flash_tween_1):
          _sight_streak_flash_tween_1.kill()
      _sight_streak_flash_tween_1 = create_tween()
      ...

B2  BIRD ANIMATION FUNCTIONS: 10+ TWEENS WITHOUT KILL GUARDS
    File: interval_birds.gd, lines 21875-22006

    _animate_bird_food_collect(), _animate_bird_peck(), and nearby functions
    create multiple tweens per call without checking for in-progress tweens:
      Line 21875: var food_tween := create_tween()
      Line 21880: var peck := create_tween()
      Line 21897: var tween := create_tween()
      Line 21914: var tween := create_tween()
      Line 21928: var tween := create_tween()
      Line 21947: var tween := create_tween()
      Line 21973: var tween := create_tween()
      Line 21988: var tween := create_tween()
      Line 22000: var tween := create_tween()

    These are triggered by user actions (correct answers, chicken feed events).
    Fast correct-answer chains (especially in Note Chase) can create 4-9
    overlapping tweens that all animate the bird simultaneously. Each Tween
    object is a reference-counted resource.

    Fix: Add _bird_action_tween: Tween instance var; kill before new animations:
      if _bird_action_tween != null and is_instance_valid(_bird_action_tween):
          _bird_action_tween.kill()
      _bird_action_tween = create_tween()

    Impact: Low (bird is decorative), but eliminates resource accumulation
    during fast gameplay.

B3  NOTE CHASE SPAWN TWEENS: NO KILL ON RE-SPAWN
    File: interval_birds.gd, lines 14456-14583

    _animate_note_chase_note_appear() (line 14456), _animate_note_chase_hit()
    (line 14501), _animate_note_chase_miss() (line 14527) each create a new
    tween per note panel. Note panels are Queue_Free'd so their tweens are
    freed too — this is the correct pattern. ACCEPTABLE AS-IS.

B4  create_timer() CREATES 40+ SceneTreeTimer OBJECTS
    File: interval_birds.gd, ~42 await get_tree().create_timer() calls

    Each creates a SceneTreeTimer (reference counted, freed on timeout).
    None are in per-frame loops. The densest cluster is in tutorial sequences
    and answer-feedback coroutines (lines 16201-16611, 20302-20539).
    The feedback delay calls (_current_post_answer_delay()) at lines 16427,
    16502, 16611, 19879, 20331 are called once per correct/incorrect answer.

    Fix: Not worth changing individually. If timer allocation becomes
    measurable, replace await create_timer() with a single-Conductor
    deferred callback. For now: ACCEPTABLE AS-IS.

B5  _sight_progress_tween / _sight_streak_anim_tween: PROPERLY MANAGED
    File: interval_birds.gd, lines 7647, 7774

    Both stored tweens are killed before recreation:
      _sight_progress_tween.kill()     # line 7647
      _sight_streak_anim_tween.kill()  # line 7774
    Status: CORRECT PATTERN, no issue.

B6  _bird_idle_tween / _bird_flap_tween: PROPERLY MANAGED
    File: interval_birds.gd, lines 22037, 22055

    Both killed before recreation:
      _bird_idle_tween.kill()   # line 22037
      _bird_flap_tween.kill()   # line 22055
    Status: CORRECT PATTERN, no issue.

C. RESOURCE ALLOCATION BEYOND M1-M9
================================================================================

C1  _layout_menu_top_gloss(): StyleBoxFlat.new() ON EVERY RESIZED — [= M9]
    Already documented in perf_improv-claude.txt as M9. Not yet fixed.
    This is the highest-priority remaining resource allocation issue.

C2  _style_menu_select_button(): 3 StyleBoxFlat PER CALL — HIGH VOLUME
    File: interval_birds.gd, lines 6131-6244 (multiple overloads)

    All overloads of _style_menu_select_button() create:
      var normal := StyleBoxFlat.new()
      var hover := normal.duplicate()
      var pressed := normal.duplicate()

    This is called for ~40-60 buttons from _refresh_*_buttons() functions.
    After M5 (skip detail functions in overview), the call count drops
    significantly. The per-button StyleBoxFlat cache (F1 pattern) could be
    applied here with a signature hash.

    Fix: Same meta-guard pattern as piano selector (F1):
      var sig := "%d|%.3f|%.3f|%.3f" % [selected, r, g, b]
      if btn.get_meta("_msb_sig", "") == sig:
          return
      btn.set_meta("_msb_sig", sig)
      # ... create and assign styleboxes

    Impact: Significant — eliminates the majority of per-refresh allocations
    once M5 is applied (detail refresh functions guarded).

C3  _setup_card_stylebox(): DUPLICATE PER CARD PER REFRESH
    File: interval_birds.gd, line ~7191 (called from _set_home_section_card_state)

    Already documented as M6 in perf_improv-claude.txt.

C4  GradientTexture2D.new() — 5 ALLOCATIONS IN _build_ui(), NONE IN HOT PATHS
    Lines 2159, 3399, 4662, 4682, 4718, 4723. All in _build_ui().
    ACCEPTABLE AS-IS.

C5  SystemFont.new() — 2 ALLOCATIONS IN _apply_responsive_touch_scaling()
    File: interval_birds.gd, lines 5104, 5114

    _apply_responsive_touch_scaling() is called on every layout/resize event.
    Each call allocates 2 SystemFont objects. SystemFont is a
    reference-counted resource that goes through Godot's font glyph cache.

    Fix: Cache the SystemFont objects as instance vars:
      var _cached_system_font: SystemFont = null
      var _cached_title_system_font: SystemFont = null

      if _cached_system_font == null:
          _cached_system_font = SystemFont.new()
          _cached_system_font.font_names = [...]
      # use _cached_system_font

    Impact: Moderate — eliminates 2 font allocations per resize. Fonts have
    large internal glyph caches; rebuilding them on each resize is wasteful.

C6  _apply_continuous_sight_skin() / _apply_sight_notes_chords_skin():
    GAME_CARD StyleBoxFlat CREATED ON EVERY SKIN APPLY
    File: interval_birds.gd, lines 8007, 8217 (new, added this session)

    Both skin apply functions create a new game_card StyleBoxFlat every call.
    _refresh_sight_notes_chords_skin() is called from _apply_responsive_
    touch_scaling() (line 5270) on every resize, and from _on_mode_selected().

    Fix: Cache as instance vars (same M1 pattern):
      var _sight_game_card_style_cache: StyleBoxFlat = null
      var _continuous_game_card_style_cache: StyleBoxFlat = null

    Impact: Low-medium — called on resize events and mode changes.

D. STRING OPS, ARRAY MUTATIONS, AND META CALLS IN HOT PATHS
================================================================================

D1  _update_continuous_sight(): 6-SUBSTITUTION FORMAT STRING EVERY FRAME
    File: interval_birds.gd, line 19481 (post our edit: ~19481)

      _progress_label.text = "LV:%d  ACC:%d%%  P:%d G:%d M:%d  COMBO:%d" % [
          _continuous_sight_level, acc, _continuous_sight_perfect_hits,
          _continuous_sight_good_hits, _continuous_sight_miss_hits,
          _continuous_sight_combo]

    GDScript % formatting allocates a new String every call. At 60 fps
    this is 60 string allocations/sec just for this label.

    Fix: Only update the label when values change:
      var new_text := "LV:%d  ACC:%d%%  P:%d G:%d M:%d  COMBO:%d" % [...]
      if _progress_label.text != new_text:
          _progress_label.text = new_text

    The comparison itself allocates a string but avoids the Label layout
    recalculation and text-render cost when the value hasn't changed.
    Alternative: track last-set values as instance vars and compare ints.

D2  _update_rhythm_flow(): SAME PATTERN AT LINE ~19604
    Same fix as D1 applies.

D3  OUR ADDITION — str() CALLS IN SKIN UPDATE BLOCK
    File: interval_birds.gd, lines 19606-19612, 19761-19767 (added this session)

      _sight_lives_hearts_label.text = str(_continuous_sight_combo)
      _sight_streak_value_label.text = str(_continuous_sight_level)

    These run every frame when skin is active. str() allocates a new String.

    Fix: Cache the last-set string and skip the assignment if unchanged:
      if _last_combo_text != _continuous_sight_combo:
          _last_combo_text = _continuous_sight_combo
          _sight_lives_hearts_label.text = str(_continuous_sight_combo)

    Or track the int value:
      if _sight_combo_display != _continuous_sight_combo:
          _sight_combo_display = _continuous_sight_combo
          _sight_lives_hearts_label.text = str(_continuous_sight_combo)

D4  _continuous_sight_notes.remove_at(i) IN BACKWARD LOOP — O(n²)
    File: interval_birds.gd, lines 19585-19619 (rhythm flow loop)
    Also: _update_continuous_sight backward loop ~19451-19464

    remove_at(i) shifts all elements after index i. In a backward loop with
    many removals this is O(n²) in the worst case. Already documented in
    perf_improvements.txt item 3.7, not yet fixed.

    Fix: Collect survivors into a new array and swap:
      var keep: Array[Dictionary] = []
      for n in _continuous_sight_notes:
          var p := n.get("panel", null) as Panel
          if p == null or not is_instance_valid(p): continue
          # ... move logic ...
          if not should_remove:
              keep.append(n)
          else:
              p.queue_free()
      _continuous_sight_notes = keep

D5  _continuous_miss_log.remove_at(0) — FRONT-REMOVAL O(n)
    File: interval_birds.gd, lines 17005, 17013-17015

      _continuous_miss_log.remove_at(0)
      _continuous_recent_miss_times.remove_at(0)
      _continuous_recent_miss_times.remove_at(0)

    Front-removal from a GDScript Array is O(n) — shifts all remaining
    elements. _continuous_miss_log and _continuous_recent_miss_times grow
    with each miss. On mobile with many misses this becomes slow.

    Fix: Use a circular buffer (Array with head index) or use append_back /
    pop_front via a PackedFloat64Array if purely numeric, or reverse the
    semantics (append at front, pop from back).

D6  185 .get_meta() / .set_meta() / .has_meta() CALLS
    These are dictionary lookups on the node's internal metadata dict.
    Acceptable individually, but the piano selector fix (F1) already shows
    that per-button meta guards are effective. The M7 and C2 fixes above
    would add more meta guards; keep their keys short to minimize hash cost.

D7  NOTE CHASE LOOP: str() CONVERSION PER NOTE PER FRAME
    File: interval_birds.gd, line ~14445

    Inside _update_note_chase() loop:
      var kind := str(n.get("kind", "note"))

    This runs for every active note every frame. str() on a Variant that's
    already a String is a no-op string copy. The Dictionary.get() call with
    a default is also a hash lookup per note per frame.

    Fix: Store "kind" as a typed enum or int constant in the note dictionary
    so the comparison is integer-based. Or apply the RefCounted note class
    from perf_improvements.txt item 3.6.
