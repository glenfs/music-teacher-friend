[FIXED] F1 — PIANO SELECTOR: 66 StyleBoxFlat ALLOCATIONS PER set_selection() CALL
  File: ui/components/virtual_piano_selector.gd

  _apply_white_key_style() created 3 new StyleBoxFlat objects per key × ~22 white
  keys = 66 allocations every time set_selection() was called. set_selection() is
  called from _apply_sight_note_selector_for_current_clef() every time
  _on_mode_selected() runs while in Sight Notes mode.

  Also: _apply_white_key_finish() was called from _apply_white_key_style(), adding
  1 more StyleBoxFlat per key per selection update = 22 extra allocations.

  Fix applied:
  - Added _ensure_key_style_cache(): creates 6 shared StyleBoxFlat objects once,
    reusing them for all keys. Invalidated when selected_color changes.
  - Added _key_sel meta guard in _apply_white_key_style(): skips all override calls
    if the key's selected state didn't change. Eliminates all allocations on repeat
    calls when the selection is the same.
  - Moved _apply_white_key_finish() call to _rebuild_keyboard() loop so gloss
    overlays are created once at build time, not on every style update.

  Impact: Notes tab becomes near-instant after first visit.


[FIXED] F2 — YELLOW TABS BUG: _home_sight_mode_row VISIBLE DURING EAR TRAINING
  File: scripts/interval_birds.gd, line ~9372

  _home_sight_mode_row (the Notes/Chords/Continuous/Rhythm Flow tab row) was
  visible during ear training detail view because sight_in_more_settings only
  considered _sight_settings_screen_active. A user clicking these tabs during ear
  training called _on_sight_mode_button_pressed() which changed _sight_mode and
  _selected_mode = MODE_SIGHT. On return to Sight Reader, the wrong sight mode
  was restored.

  Fix applied:
  - Added guard: hide _home_sight_mode_row when show_detail is true and
    _selected_mode is not MODE_SIGHT or MODE_NOTE_CHASE.

  Impact: Prevents accidental sight mode changes during ear training.


[FIXED] F3 — HOME/BACK BUTTON BLOCKS UI BEFORE REFRESHING
  File: scripts/interval_birds.gd, line ~9951

  _on_home_mode_back_pressed() called _on_mode_selected() synchronously. Since
  _on_mode_selected() runs ~12 refresh functions (each iterating over dozens of
  buttons with StyleBoxFlat allocations), the button press input was processed
  before the engine rendered the pressed state. The button appeared unresponsive.

  Fix applied:
  - Changed _on_mode_selected() to call_deferred("_on_mode_selected") in
    _on_home_mode_back_pressed(). The button press renders immediately; the heavy
    refresh runs on the next frame.

  Impact: Back/Home button feels instant; refresh still happens within ~16ms.

M1  _refresh_practice_setup_theme(): StyleBoxFlat.new() FOR SECTION CARD EVERY CALL
    File: scripts/interval_birds.gd, line ~6740

    Each call to _refresh_practice_setup_theme() allocates a new StyleBoxFlat for
    the active section card (lines 6740-6753):
      var section_style := StyleBoxFlat.new()
      section_style.bg_color = ...
      section_style.corner_radius_* = ...
      section_card.add_theme_stylebox_override("panel", section_style)

    This function is called every _on_mode_selected() (which runs on every tab
    click, hub press, and back press).

    Fix: Cache the section card StyleBoxFlat as an instance var. Only rebuild
    when the active section changes:
      var _practice_section_style_cache: StyleBoxFlat = null
      var _practice_section_style_for_section: VBoxContainer = null

      if _practice_section_style_cache == null or
         _practice_section_style_for_section != active_section:
          _practice_section_style_cache = StyleBoxFlat.new()
          ...
          _practice_section_style_for_section = active_section
      section_card.add_theme_stylebox_override("panel", _practice_section_style_cache)


M2  _refresh_practice_setup_theme(): ALSO CREATES StyleBoxFlat FOR TABS SHELL
    File: scripts/interval_birds.gd, lines ~6766-6778

    Lines 6764-6779 create another new StyleBoxFlat for _sight_notes_tabs_shell
    every call when _selected_mode is MODE_SIGHT or MODE_NOTE_CHASE. This is a
    second allocation on every mode-change in sight/note-chase modes.

    Fix: Cache this shell StyleBoxFlat too. It doesn't change between calls.


M3  _refresh_sight_notes_setup_menu_style(): _apply_menu_setup_theme_to_home()
    RUNS BEFORE SIGNATURE CHECK
    File: scripts/interval_birds.gd, line 6322

    _apply_menu_setup_theme_to_home() is called at line 6322, BEFORE the signature
    check at line 6335. Even if the signature matches (meaning the rest would be
    skipped), this function always runs on the first call per _on_mode_selected()
    cycle (the _setup_theme_dirty flag ensures it runs once per cycle).

    This is not a bug since _apply_menu_setup_theme_to_home() has its own cache,
    but the call overhead is unnecessary after the first run within a cycle.

    Fix: Move _apply_menu_setup_theme_to_home() call to before the first
    _refresh_sight_notes_setup_menu_style() call in _on_mode_selected() and
    remove the call from inside _refresh_sight_notes_setup_menu_style(). Same
    for _refresh_practice_setup_theme().


M4  _refresh_home_section_emphasis(): RUNS 8 _set_home_section_header_state() CALLS
    File: scripts/interval_birds.gd, line ~7203

    Called from _on_mode_selected() every time. It calls _set_home_section_header_state()
    8 times, one per section. Each of those checks and potentially modifies
    section header styles.

    When on the overview (not detail view), none of the sections are visible so
    all 8 calls are wasted.

    Fix: Add early return if not _home_mode_detail_active:
      func _refresh_home_section_emphasis() -> void:
          if not _home_mode_detail_active:
              return
          ...


M5  _on_mode_selected(): CALLS DETAIL REFRESH FUNCTIONS IN OVERVIEW MODE
    File: scripts/interval_birds.gd, lines 9397-9410

    _on_mode_selected() always runs all 12 refresh functions even when
    _home_mode_detail_active = false (overview). The functions themselves have
    early returns but the call overhead and dictionary/array iterations still add up.

    Functions safe to skip in overview mode:
      _refresh_ear_mode_buttons()       — only shown in ear detail
      _refresh_clef_buttons()           — only shown in sight detail
      _refresh_note_chase_clef_buttons() — only shown in chase detail
      _refresh_chord_group_buttons()    — only shown in chord detail
      _refresh_progression_pattern_buttons() — only shown in progression detail
      _refresh_scale_mode_buttons()     — only shown in scale detail
      _refresh_cadence_buttons()        — only shown in cadence detail
      _refresh_home_section_emphasis()  — see M4 above
      _refresh_sight_notes_setup_menu_style() — irrelevant in overview
      _refresh_practice_setup_theme()   — irrelevant in overview

    Fix: Wrap the detail-only functions in a guard block:
      if _home_mode_detail_active:
          _refresh_ear_mode_buttons(false)
          _refresh_clef_buttons(false)
          ...
