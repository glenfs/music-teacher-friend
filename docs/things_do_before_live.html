Things To Do Before Going Live — Clefira (Paid)

Honest pre-launch assessment of what's ready, what isn't, and a 15-working-day path to commercial readiness.

TL;DR

The feature breadth is already past most paid competitors. The commercial readiness isn't there yet. If you shipped today at $5 / month you'd get refunds; if you ship at $15 / month with another 4–6 weeks of polish you'd hold your own against EarMaster / Tomplay / Yousician in the teacher-plus-student niche where none of those three actually fits.

Recommendation: position as Pro tier with a 14-day free trial, not a cheap student app. The depth justifies it; cheap pricing trains users to undervalue.

What's strong (ship-worthy today)

  • Smart Drill Library — 16ths, triplets, jazz ii-V-I, stride bass, walking bass, chord exercises, Hanon, Czerny, scales in 3rds/6ths/chromatic/contrary. This catalog is competitive with EarMaster ($60+) and broader than Hanon Online (subscription).
  • MIDI grading pipeline — capture + score + replay-your-take + accuracy gate + weak-spot drill + per-note keyboard feedback. This is the kind of feature that justifies "pro" pricing on its own.
  • Procedural generation with seed reproducibility — teachers can give a student a seed and get the exact same drill. Genuine differentiator.
  • Daily Drill + streak + analytics + lesson summary export — the engagement loop is real, not gamification theater.
  • Teacher edition concept — addressable to a paying segment (piano teachers) who currently cobble together 3–4 apps to do what you're proposing.
  • Practice Drills visual polish — hero dock, chips, post-play summary, contextual styling — reads as a paid product, not a free one.
  • QA pipeline — orchestrator drives the shipped .exe end-to-end. Genuinely rare for a small app.

Real gaps that would hurt at launch

Cross-module polish unevenness. Practice Drills got 30+ refinement rounds this month. Sight Reading, Ear Training, Note Chase — unclear if they got the same love. Customers will compare modules side-by-side and notice. UI 20 (cross-module style unification) is the obvious follow-on but it's multi-day work.
Customer can't tell what's beta. Sight Singing is gated behind a flag because it's not ready — correct, but if a paying user discovers a half-working feature with no "beta" label, refund. Audit every entry point.
MIDI-keyboard dependency is poorly explained. Most of the pro features (grading, accuracy, weak-spot, replay-your-take) silently degrade or hide when there's no MIDI device. A first-run check that explicitly says "For best results, plug in a MIDI keyboard — these features will activate: ..." would prevent confusion.
Onboarding for a brand-new user. No clear tutorial for "you've opened Clefira, what now?" — Yousician's first 30 seconds explain piano-app behavior with zero text; Clefira drops you into a home menu with 8 modes. A 4-screen first-run flow would massively reduce bounce.
Audio quality. A2–C6 piano samples are fine for ear training; for a paid music app, students expect concert-piano warmth. Either license a high-quality sample set ($100–500) or document the choice as a deliberate "drill" sound.
No telemetry. If you ship paid and someone has a bug, you'll never see it. Even basic crash logging + "what feature is used most" would tell you where to invest the next 6 months of dev. The QA pipeline catches regressions; telemetry catches user reality.
Saved files location is opaque. Already had a "where did my PDF save?" question from internal testing. For paying customers that's a –1 star review. Add "Open exports folder" button. (One-day task.)
Teacher dashboard UX. The teacher-assignment data model exists; the UI for creating assignments doesn't. A teacher buying Pro expects to assign drills to students within 60 seconds of opening the app. Right now they'd have to edit JSON.
No social proof. Zero reviews, zero install base. New paid app from unknown developer = high friction. Mitigation: free tier or generous trial to get people through the door.

Hard blockers (cannot ship paid without these)

No payment integration shipped. Google Play Billing plugin is installed per memory but the actual upgrade flow isn't wired. Needs purchase UI, restore-purchases flow, license validation, refund handling.
License + EULA still placeholder. Per memory: hard blocker for paid distribution.
No code signing certificate. Hard blocker — Windows SmartScreen will warn on every install, which kills conversion. Cost: ~$200–400/year.
Cloud sync not validated cross-device. Backups exist but multi-device sync hasn't been tested end-to-end. Multi-device is table-stakes for paid.

The honest punchline

The product is good enough to charge for. The business around it isn't quite ready. Don't conflate "the code works" with "ready to ship paid" — they're different problems. The code is the easy part; payment, support, marketing, refunds, reviews are where most small apps die.

If you want to validate demand before doing all the business plumbing, the lowest-friction move is: post Practice Drills as a free standalone, get 100 users, see what they ask for. That'll tell you in 2 weeks what 2 months of internal speculation can't.
