AI-Orchestrated QA Pipeline Clefira

External Python driver that talks to a running Clefira.exe via an in-game HTTP debug API, runs YAML test cases, captures structured results, and hands them to an LLM for triage. Complements the existing in-engine QA harness (qa_run.ps1 + scripts/qa/qa_runner.gd).

Deliverables

Each item below is a real file in the repo. Paths are relative to the project root.

scripts/qa/debug_server.gd — Godot 4 GDScript HTTP server. TCPServer + a minimal HTTP request parser (no third-party deps). 11 endpoints: /health, /state, /logs, /mode, /drill/{start,stop,play}, /midi/inject, /audio/probe, /assert, /screenshot, /quit. Bound to 127.0.0.1 only; opt-in via --debug-server [port] flag (wired into interval_birds.gd next to the existing --qa parsing).
qa/orchestrator/qa_orchestrator.py — Python 3.10+ orchestrator. Launches Clefira.exe with --debug-server, polls /health until ready (30 s timeout), reads test_cases.yaml, runs every case step-by-step via the DebugClient wrapper, writes results/qa_results.json + results/qa_logs.json + screenshots. Exit codes: 0 = pass, 1 = test failures, 2 = config error, 3 = unreachable server. Supports --no-launch (attach to running game), --tag and --name filters, --windowed mode.
qa/orchestrator/midi_mock_setup.py — MidiSink class that picks the best available backend: real virtual port via mido + python-rtmidi when a driver's available, falls back to debug_server.gd:/midi/inject when not (CI default). Timestamps every send to midi_trace.json for the LLM latency analysis. Includes compute_midi_audio_latency() helper that pairs sent notes with audio-probe events.
qa/orchestrator/test_cases.yaml — Data-driven fixtures. 9 cases covering smoke (debug server health, mode transitions, scale generate + play + audio probe), MIDI roundtrip (8 taps against the C major scale checking accuracy ≥ 50%), Smart Drill Library coverage (16ths, jazz ii-V-I, stride bass), 8vb bass rendering, and settings sanity. Marked # CUSTOMIZE: lines where teams will tweak thresholds.
qa/orchestrator/llm_qa_analysis_prompt.md — Structured Claude / GPT prompt that takes the JSON blobs + screenshots and produces a triage report distinguishing regressions vs flakes vs state bugs vs MIDI drift. Forces a fixed Markdown output template so the team can read every report in < 2 minutes. Includes severity mapping (smoke + state-affecting members = blocker, etc.) and a context-window budget rule for large runs.
qa/orchestrator/setup_and_run.md — Setup docs: Python deps, optional virtual MIDI driver per OS (loopMIDI / IAC / ALSA), how to export Clefira with debug-server support, three running modes (auto-launch, attach, filtered), GitHub Actions integration, and the 3-step validation checklist.
qa/orchestrator/requirements.txt — Pinned to forward-compatible ranges: requests<3, PyYAML<7, mido<2, python-rtmidi<2.
.github/workflows/qa.yml — Extended with a new qa_orchestrator job that runs after the existing in-engine harness (so it only fires when compile / scripts are already green). Caches Godot via the existing cache, background-launches Clefira with --debug-server, runs the orchestrator with --no-launch, uploads results/** + the Clefira stdout/stderr logs as qa-orchestrator-${run_id} artifacts, surfaces the pass/fail summary into the GitHub Step Summary.

How to use it

Local interactive (sanity check)

# Terminal 1 — launch Clefira with the debug server enabled
$env:GODOT_BIN = "C:\Path\To\Godot_v4.6-stable_win64.exe"
& $env:GODOT_BIN --headless --path . -- --debug-server 8765

# Terminal 2 — install deps + run the orchestrator against it
cd qa\orchestrator
python -m pip install -r requirements.txt
python qa_orchestrator.py --no-launch --port 8765 --tag smoke --verbose

CI / full run (orchestrator auto-launches Clefira)

python qa/orchestrator/qa_orchestrator.py --build build/Clefira.exe --verbose

LLM analysis

After a run, paste llm_qa_analysis_prompt.md + the contents of qa_results.json / qa_logs.json / midi_trace.json into Claude or GPT. The prompt forces a structured triage report distinguishing regressions, state bugs, MIDI drift, and flaky tests.

3-step validation checklist

Run these in order after installing. All three should pass before trusting CI integration.

  1. Debug server reachable 
    curl http://127.0.0.1:8765/health
    Expect HTTP 200 with {"ok": true, ...}. Confirms the export includes debug_server.gd and the --debug-server flag wired in.
  2. Orchestrator runs the smoke tag clean 
    cd qa/orchestrator
python qa_orchestrator.py --build ../../build/Clefira.exe --tag smoke --verbose
    Expect exit 0 and results/qa_results.json showing summary.passed > 0, failed == 0. Confirms the dispatch table works end-to-end.
  3. MIDI smoke 
    python midi_mock_setup.py
    Expect a single line midi sink mode was: virtual (or debug_api fallback) plus ./midi_smoke_trace.json written with 7 events (4 single notes + a 3-note chord). Confirms either the virtual MIDI driver or the debug-API fallback path is wired.

Why this complements (not replaces) the in-engine harness

  • In-engine (qa_run.ps1) — fastest feedback loop, runs scripted scenarios from inside the engine, exits with a pass/fail code. Used for compile-health + per-module QA matrix on every PR.
  • External (this pipeline) — drives the shipped binary end-to-end. Catches the bug class where scripts compile cleanly but the exported game misbehaves (missing assets, wrong export flags, debug-only autoloads, MIDI device init order, etc.). Also unlocks LLM-assisted triage on long runs.

Smoke QA stays green after the pipeline was added — no existing functionality regressed.
